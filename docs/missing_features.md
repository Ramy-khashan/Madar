# اللي ناقص في التطبيق

تدقيق من الكود الحالي فقط. اللي شغال ما انذكر هنا.

---

## فردي (Individual)

### تفاصيل العقار (للمشتري)
- حالة النشر (`publicationStatus`: PENDING / APPROVED) موجودة في الموديل وما تظهر في الواجهة.
- خدمات التقسيط والتأمين على صفحة التفاصيل معطّلة بالكامل (الكود معلّق).
- زر «عرض طلبي» بعد إرسال الطلب ما يفتح الطلب؛ ينفّذ نفس عملية الإرسال مرة ثانية.

### طلباتي
- القائمة تجيب البيانات، لكن البطاقة بدون ضغط: ما في تفاصيل، حذف، أو تغيير حالة.
- الـ API موجود (`GET /requests/:id` و`DELETE` و`PATCH status`) وما في واجهة تستدعيه.

### عقاراتي وملف العقار
- الفردي يقدر يشوف الملف ويرسله للوسيط أو يحذفه، **ما يقدر يعدّل** الاسم أو المصاريف أو يحفظ (التعديل للوسيط فقط).
- من ملف المبنى متعدد الوحدات: ما في زر «إضافة وحدة».

### العقود
- زر تحميل PDF فاضي.
- الفردي ما يقدر يوافق أو يرفض العقد (الأزرار للوسيط فقط).

### التأمين وتقسيط الإيجار
- الشاشات تعمل ببيانات وهمية (mock) وما في استدعاء API.
- تأكيد التأمين/التقسيط يعطي رقم طلب وهمي بدون حفظ.
- زر «عرض السبب» في طلب تقسيط مرفوض فاضي.

### تقييم العقار
- تبويب طلباتي: استدعاء الـ API معلّق، القائمة تطلع فاضية دائماً.
- التقييم المعتمد: شركات وهمية، والإرسال وهمي (ما يروح للسيرفر).
- زر تحميل PDF فاضي.

### المفضلة
- زر الدردشة من المفضلة يفتح المحادثة **بدون بيانات الطرف** (الـ extra معلّق) — الرحلة ناقصة/تنكسر.

### الحساب
- الشروط والدعم: الشاشات مربوطة في الراوتر وفاضية حالياً.
- تفعيل/إيقاف الإشعارات يتغيّر محلياً فقط (ما ينحفظ ولا يروح للسيرفر).

## وسيط (Broker)

### الرئيسية والعقارات
- شاشة عقارات المالك (`ownerProperties`) كلها معلّقة: المسار والشاشة معطّلين.

### ملف العقار والتعديل
- الحفظ يرسل **العنوان واسم المشروع فقط**. باقي الحقول (المساحة، الطابق، الغرف، السعر…) ظاهرة للعرض وما تُحفظ.
- في المبنى متعدد الوحدات: ما في حقول تعديل للاسم، وما في إضافة وحدة من الملف.
- تفاصيل الوحدة: المساحة/الطابق/الغرف/الإيجار غير قابلة للتعديل. بيانات المستأجر وتواريخ الإيجار موجودة في الـ bloc وما تظهر في الواجهة وما تُرسل للـ API.
- المفضلة (البوك مارك) على ملف العقار تتبدّل محلياً فقط بدون API.
- الرسم البياني المالي القديم (خط الدخل/المصروف) معلّق. الموجود حالياً: 3 أرقام فقط بدون مخطط.

### الاشتراك
- بطاقة الاشتراك في الإعدادات: الضغط فاضي.
- خطط الاشتراك والدفع وهمية (mock + تأخير ثانيتين بدون بوابة دفع).

### التقارير
- فلتر النطاق يعيد جلب البيانات. اختيار عقار معيّن ما زال بدون قائمة اختيار عقار.

### التطوير العقاري
- زر تحميل تقرير PDF في مرفقات المشروع فاضي.

## مدير مشروع

- يدخل شاشة مستقلة بدون شريط التنقل: لا دردشة، لا عقود، لا إضافة عقار، لا مفضلة.
- قائمة الحساب: لغة + تسجيل خروج فقط. ما في تعديل الملف، إشعارات، شروط، دعم، أو حذف حساب.
- المهمة المخصصة في تفاصيل المرحلة تُكتب في الحقل وما تُرسل مع الـ API (الجزء معلّق).
- ما يقدر ينشئ مشروعاً (الإنشاء من حساب الوسيط).

## عام / تقني

### مسارات وشاشات ناقصة أو ميتة
- `smartAssistantIntro`: الشاشة موجودة والمفتاح موجود، **ما انربطت في الراوتر**. التطبيق يروح مباشرة للدردشة.
- `ownerProperties`: المسار والشاشة معلّقين.

### إشعارات
- العقد والعقار يفتحان شاشة. باقي الأنواع ما تفتح شيء (أو تظهر «قريباً»).

### حالة النشر
- `publicationStatus` يُقرأ من الـ API وما يظهر في أي بطاقة أو تفاصيل.

### مبنى أب / وحدات
- اختيار المبنى الأب موجود عند إضافة شقة ويُرسل مع الإنشاء.
- بعد الإنشاء: ما يتعدّل الأب، وما في إضافة وحدة من ملف المبنى.

### API موجود وما يُستخدم من الواجهة
- `incomingRequestAction`
- تفاصيل/حذف/تغيير حالة الطلب (`propertyRequestById`, `propertyRequestStatus`) — الـ API موجود، شاشة طلباتي ما تستدعيه
- تقييمات العقار (`propertyEvaluations`) مذكور في كود معلّق وغير معرّف في `end_points.dart`
